# REVIEW.md 通用示例

按实际产品、平台和风险适配；示例不代表项目已经实现这些机制，也不是已完成验收的证明。只检查当前改动涉及的条款。

## 范围与发现

检查本次新增、放大或触发的行为错误。每项写位置、触发条件、证据、用户影响和验证方式；未触发的历史债务另列。代码与安全分别检查，同根因合并记录，纯风格交确定性工具处理。外部替代只提建议，未经采纳不修改方案。

## 功能与状态

- 从真实用户入口核对可观察验收目标。首次使用与已有配置分别检查，不用开发者前置操作隐藏用户成本。
- 输入、对象身份、权限与版本应来自一致的请求状态；切换对象或重试不得串用其他请求的数据。
- 只有真实持久化或外部成功回执才报告完成，并提供可定位结果；生成文字、等待中及结果未知不能冒充成功。
- 参数错误给出字段和约束，失败不能进入成功分支。重试避免重复创建、发送或其他副作用。
- 区分拒绝、断线、超时、取消与结果未知。未知结果先核对，恢复不能丢失草稿或仅修改文案而继续锁死。

## 安全与数据

- 按实际主体、资源和动作核对执行边界，不以页面隐藏代替授权。拒绝、撤销和权限变更应一致生效。
- 外部路径、URL、模型和附件内容不可信；不得借内容指令扩大工具或资源权限。
- 日志、截图和报告使用最小脱敏证据，不记录可用凭据或用户私有数据。
- 保持稳定身份、关联、存量数据和版本兼容；破坏性操作及外部真实账户验证须在授权范围内进行。

## 证据与验收门槛

实现者先实际运行、自检并按需截图，再交独立审查。截图放 PR 评论／附件，不进代码分支。证据对应精确 SHA，分别报告真实服务、mock、静态检查、未测与阻塞；无 UI 改动不伪造截图。

代码和安全共享最多三轮：首轮审完整 diff，后两轮检查增量、既有发现及影响回归。换代理、模型、重试或 restack 不重置；超限仍有未解问题交协调者请求决策，不自动通过。

协调者检查最终必要 CI 与组合版本；冲突解决或代码改变后补回归并更新证据。合主前须用户本人测试并明确确认对应版本；发布、部署按各自授权处理。涉及实际安装包交付时，另按已安装的 `yushen-release-acceptance` 验证最终产物；不把纯文案改动扩成整套安装验收。

## 接入 AGENTS.md 的最小段落

审查当前变更时，读取仓库根目录 REVIEW.md 的适用条款，并按任务读取代码质量和安全审查技能。引用不保证正文自动加载；读取失败或规则与实际代码不符须报告，不能假装已执行。

逐轮发现、日志和修复证据留在 PR；模型选择、安装教程、完整聊天与历史缺陷清单不放入长期审查规则。
