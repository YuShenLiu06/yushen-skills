# 用户目标优先：走完最短完整路径

用“十岁孩子能理解、八十岁老人能操作”检查是否依赖专家常识。这是易懂易用的检验比喻，不预设真实用户年龄，也不使用幼稚或居高临下的表达。好懂是起点，完整做成事情才是终点。

## 设计完整路径

1. 写清用户、场景、目标和可观察的完成结果。例如目标是“给指定联系人发消息”，而非“做一个聊天页面”。
2. 从真实入口分别列出首次使用、日常使用的全过程。下载、授权、配置和切换应用都算步骤；同时比较操作数、决策数、重复输入、等待和恢复成本，不能把负担藏进前置条件或一页界面。
3. 在已有授权内自动发现已有部署、配置和进度，填入已知信息。低风险选项给可见且可改的合理默认值；指令和配置已能确定目标时不再询问，只有真实歧义或后果需要用户判断时才问。缺少权限、网络失败和确实不存在必须区分。
4. 找到安全、清晰、可恢复的最短可行路径。每一步都须有信息需求、用户决策或风险控制的理由，无必要就删除。必要授权、高风险确认要说清范围与后果并保留；默认值不代替不可逆决定，外部动作也不一定能撤销。

例：已在会话中，直接“输入 → 发送”，不重复选择联系人；发送结果由系统反馈。安装器应自动检查已有部署：唯一匹配就展示目标，多个匹配且仍无法判断时才请用户选择。普通用户能下载、双击、按引导完成，不以 clone、终端或另装依赖为使用前提。

学习产品自动处理整理、排期和归档，保留学习目标所需的回忆、推理与尝试；新增学习理论先解释逻辑与证据，获用户明确认可后才进入产品。

## 融入已有界面，按需出现

- 以用户当前目标组织界面，不把内部模块、实现步骤或新增能力逐一变成功能区。优先复用原页面、原内容位置和已有入口；同一动作保留一个清楚的主要视觉入口。
- 实现前检索并阅读已有组件、业务封装、交互、服务和已安装依赖，优先复用、组合或兼容扩展；仅补明确能力缺口，不为少量相似制造过度通用抽象。快捷键、右键等便捷入口共用同一能力和状态，不分别实现。
- 默认不额外新增功能区或常驻按钮。只有核心、高频、必须持续可见的操作，或现有入口无法清楚承载的重要能力，才考虑独立区域或强入口；说明它解决的具体用户问题，不能仅因“新增了功能”就新增面板。
- 临时任务的控件随任务出现、完成后退出。无待处理内容时隐藏相应标题、计数、横幅、空面板和操作栏；首次使用引导、必要状态或错误恢复确有用途时再保留，不隐藏用户必须知道的信息。
- 操作贴近作用对象，明确作用范围，保留用户当前任务的上下文；避免在不同位置重复堆放相同操作。具体产品的布局、控件名称和功能示例留在该项目的设计记录中，不写成通用技能的默认规则。
- 规划版面前，按相似任务与功能逻辑寻找成熟产品，在当前访问权限与任务范围内核对官方说明或实际界面，借鉴其布局和操作组织；不能核对时说明限制，不虚称已验证。说明为何适合当前用户及未沿用的行为边界，不机械照搬外观、功能数量或持久化、权限语义。最常用的操作和用户最需要的信息应触手可得，不因模仿成熟布局增加寻找、切换或操作步骤。
- 用途重复、逻辑相同或存在包含关系的操作应合并为一次完整应用，避免让用户重复设置或确认；例如版面设置已包含纸张比例时，应用版面就应一并应用比例。只有明确的独立使用需求才保留独立操作，并让作用范围清楚可见。
- 复用当前界面的圆角与曲线、色彩、间距、组件及交互风格；同级控件保持一致，不因新增功能另建视觉体系。标签、输入、内容边缘与主要操作区按层级对齐。
- 保持主要操作区稳定可达，长内容在合适的区域内滚动；检查窗口缩放、长结果及内容展开后的对齐和操作可达性，避免内容增长把主要操作挤出视野。
- 审查时逐一问：这块区域／按钮是否必须常驻？能否放回已有页面或只在相关状态出现？移除后会不会损害发现、完成或恢复？以答案决定取舍，不靠增加控件展示工作量。

## 状态、反馈与恢复

- 用用户目标命名，按钮写具体动作。错误说明“哪里出错、当前结果、下一步怎么办”，不只显示代码，不要求先读长文档再操作。
- 每个异步步骤说明在等谁或什么、当前阶段、完成判据和下一步；按服务行为设合理超时，能定位卡点。不编进度，不永久转圈。
- 允许取消、返回或安全重试。取消时停止能停止的未完成动作，说明是否只停止等待；不能误称外部操作已撤回。
- 保留合理输入，重复点击不重复执行；结果未知先核对外部状态再重试。重启后识别已完成与未完成步骤，接续进度，避免盲目重装或重新授权。
- 真正装好、授权成功或目标完成才报成功；等待、失败和未知如实显示。预演、打印 plan、启动进程都不是完成证据。
- 检查键盘操作、焦点、字号、对比度和触控目标，照顾不同能力的用户，不能只凭视觉截图验收。

## 按目标闭环验收

- 用具体场景走完整路径，记录起点、用户动作、系统动作、成功证据和恢复方式。按相关风险检查首次使用、已有配置、权限不足或被拒、慢网／断网、取消、重复点击、返回、关闭重开与恢复。
- 每屏都能回答“我该做什么、现在等什么、失败后怎么办”。涉及实现交付时，在授权范围内修复流程问题并实现自动检查，不能拿手动检查文档顶替；仅审查或设计时明确待实现与未验证项，不声称已经修复。涉及打包交付时另验实际产物。
- 检查是否存在重复应用、冗余入口或无必要常驻区域；用实际任务确认关键操作与信息易于找到，展开长内容和调整窗口后仍对齐、可操作，新增元素延续已有风格。
- 没有真实用户测试，只能称设计检查或内部测试，不得声称“普通用户已验证”；视觉精美和支持恢复的文字声明都不能代替实际任务成功。

反例：安装器只打印 plan 却显示成功，或“一键完成”隐藏新增权限，即使点击很少也不合格。
